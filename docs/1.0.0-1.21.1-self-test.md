- Java 21.0.12.1、Minecraft 1.21.1、Fabric Loader 0.16.13、Fabric API 0.115.6。

- AMS 测试使用本机已有 `carpet-ams-addition-v26.3-mc1.21.1.jar.disabled` 的独立副本，以及 Carpet 1.4.147+v240623。这里 **26.3 是 AMS 模组版本，不是 Minecraft 版本**。
- AMS 文件 SHA-256：`7abd3f32569a8123c8291ef62d9963bad76ef6ab8851d1c264d9b9dff8ccf0f6`。

## 发现及根因修复

真实 AMS 启动并执行 `/carpet largeShulkerBox true` 后，旧适配仍返回未启用，GameTest 的 `AMS enabled shulker rule must be detected` 断言失败。该 AMS 使用 `club.mcams.carpet.AmsServerSettings`，而此前无反射适配只识别 `carpetamsaddition.CarpetAMSAdditionSettings`。

修复为通过 Fabric 模组文件元数据选择新、旧 API，然后由分离的内部适配类直接读取公开布尔字段。没有反射，没有 AMS Mixin 注入，没有向运行包打入 AMS 设置替身类。无 AMS 时不加载可选 API。

## 已执行的检查

68 项基础回归检查：包含原版 QuickShulker 四字节协议双向编解码、配置及容量保护。此项不是实际两端混装登录测试。

以下 5 组原生服务端 GameTest 在 **无 AMS** 和 **真实 AMS** 两种环境中运行；使用 Fabric 的嵌入式模拟玩家，不是真实游戏客户端：

客户端执行 `runClient`，已完成客户端初始化、Mixin 加载及资源图集加载。随后桌面工具返回 `Computer Use was not approved to use java`，未取得游戏窗口操作权限。未尝试绕过该权限。

## 可复现命令

2026-10-19 保存格式修复后重新运行以下完整命令成功，产物归档为 `mod-builds/20261019-193019/quickshulkermore-1.0.0-1.21.1-test-20261019-192543.jar`，普通与 AMS 的 XML 报告一并保存在该目录。此包补齐旧版合成器锁定数据缺少的方块实体 ID，替代此前未覆盖完整物品序列化的测试包。

```powershell
./build.ps1 -Version 1.21.1 -JavaHome 'D:\java\jdk-21_windows-x64_bin\jdk-21.0.12.1' -Tasks @('build','runAmsWorldRegression','printArtifactName') -GradleArguments @('-PlocalCompatDependencies=true','--offline','--console=plain','--no-daemon')
```

AMS 任务需先将上述两份真实依赖副本放入 `build/ams-world-regression-run/mods/`。普通 `build` 不要求 AMS；它会运行基础检查和无 AMS GameTest。XML 报告分别在两个运行目录的 `reports/` 下。
