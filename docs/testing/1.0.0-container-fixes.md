# 1.0.0 Fabric 容器修复同步（2026-10-20）

本次将已经完成的 1.21.1 修复同步到其余 14 个 Fabric 目标。26.3 仍是主开发版本；本页不声明 NeoForge 已完成本次同步。

【BUG表象】：首次打开陶罐出现箱子界面，随后槽位错乱；从其他界面打开合成器时收到属性同步包并断开。普通箱子、漏斗等还会拒绝存入另一件同类容器。

【真实根因】：Fabric 已将自定义包的接收回调调度到客户端线程，菜单通知回调再次调用 execute，受到 Minecraft 可重入执行器的排队规则影响，落到了原版菜单打开和内容包之后。迟到的通知会被后续菜单消费。另一个问题是槽位把整个物品类型当成源容器自身，禁止了所有同类物品。

【修复方案】：在 Fabric 已调度的回调中直接应用菜单通知；将普通存储槽的同类物品限制缩小到源 ItemStack 的引用身份。保留源槽及祖先源槽保护、潜影盒和收纳袋限制，以及原生燃料/输出等槽位规则。沿用既有消息格式、菜单注册形状、配置和版本号，不使用反射。

【修改代码】：Yarn 源码的接收回调现在直接调用以下方法，26.x 对应调用 MenuTypes.preparePortableMenu：

```java
(payload, context) -> PortableMenuEnvelope.prepareClient(payload.kind())
```

普通存储槽的条件保留完整的潜影盒保护，仅替换身份比较：

```java
return active() && stack != host
    && (!ShulkerUtils.isShulkerItem(host) || !ShulkerUtils.isShulkerItem(stack));
```

【回归校验】：菜单顺序测试使用实际 Minecraft 可重入执行器，先重现旧回调的首次打开回退和残留通知，再验证修正后的连续菜单选择、布局和合成器属性同步。测试不会吞掉越界异常。新增 sameTypeContainerNesting 世界测试覆盖箱子、陷阱箱、木桶、漏斗、投掷器、发射器，实际执行带内容的子容器 Shift 放入、持久化重开、取出、物品守恒和源引用保护，并保留大潜影盒拒绝其他颜色潜影盒的断言。

每个版本使用对应游戏和 Java 21/25 独立构建，build 包含组件/协议检查及测试世界；每个成功包分别归档、记录 SHA-256，并核对元数据和测试/API 类未泄漏。1.21.1 使用先前本日已通过的修复包，其普通及真实 AMS 测试各 6 项通过。本次其他版本运行普通测试环境，不把结果描述为这些版本的 AMS 联合运行、实际客户端界面或原版/More 混装登录验证。

测试适配过程中发现过 createTask 的接口可见性差异、GameTest 注解差异，以及 26.3 染色物品常量归并；均在测试覆盖层按对应版本接口处理后重新构建。失败轮次不列入交付。日志仍保留过期 daemon Java 路径提示、模拟玩家 API 弃用提示和缺少可选 Reinforced Chests 的配方告警，不声明零告警。

## 手动验收

1. 完全退出游戏，选择对应版本的单个 jar 替换旧包，再启动游戏。
2. 刚进入世界就打开陶罐；连续切换陶罐、箱子、展示架（存在的版本）和合成器，核对首次界面与物品槽位。
3. 从其他容器界面的玩家背包快捷打开合成器，验证锁槽和合成，确认不再断开。
4. 将装有物品的箱子放进另一只箱子，对漏斗等重复，测试普通点击、Shift、关闭重开和取出后的内容与数量。
5. 确认正在打开的源物品仍不能移走或放入自身，潜影盒和收纳袋限制保持，AMS 两项大容量规则打开后的第 54 格仍可保存。

本地测试包带时间戳；既有 GitHub Actions 正式构建去时间戳规则未改动。
