# QuickShulker 3.3.0 / Minecraft 26.3

## 范围与根因

本轮只修改 `versions/26.3-fabric` 与 `versions/26.3-neoforge`，使用 Java 25。根目录 1.21.1 源码保持原样；其他游戏版本等待 26.3 游戏内验收后再同步。

旧实现将不同容器映射到通用存储菜单，槽位数、物品限制和交互语义不等同于原生容器；合成器只有存储，无法执行配方。旧配置只有两个平铺权限布尔值，缺少逐类开关。修复以容器类别为统一入口，分别创建原生菜单或真实容量的自定义菜单，不修改 AMS 代码或注入 AMS 节点。

## 配置界面与命令

新增“快捷容器”页签，第一行“快捷容器（主开关）”点击循环：

- 创造可用：`quickContainers=true`、`quickContainersCreativeOnly=true`，默认值。
- true：开启，所有非旁观模式玩家可用。
- false：关闭所有此组容器，不重置各子项。

其后 14 个子项均为可点击的独立布尔开关，默认 true：

| 子配置 / OP 指令名 | 容器 | 实际槽位与菜单 |
| --- | --- | --- |
| quickChest | 箱子 | 27，箱子 |
| quickTrappedChest | 陷阱箱 | 27，箱子 |
| quickCopperChest | 全部氧化、涂蜡铜箱子 | 27，箱子 |
| quickBarrel | 木桶 | 27，箱子 |
| quickShelf | 全部木材展示架 | 3，专用菜单 |
| quickHopper | 漏斗 | 5，漏斗 |
| quickDropper | 投掷器 | 9，九宫格 |
| quickDispenser | 发射器 | 9，九宫格 |
| quickDecoratedPot | 陶罐 | 1，专用菜单 |
| quickCrafter | 合成器 | 9 输入、锁槽、只读预览、合成按钮 |
| quickFurnace | 熔炉 | 3，原生熔炉 |
| quickSmoker | 烟熏炉 | 3，原生烟熏炉 |
| quickBlastFurnace | 高炉 | 3，原生高炉 |
| quickBrewingStand | 酿造台 | 5，原生酿造台 |

命令示例：`/quickshulker quickContainers creative`、`/quickshulker quickContainers true`、`/quickshulker quickCopperChest false`。省略参数查询；需要权限等级 2。旧 `quickContainersCreativeOnly` 命令继续兼容。

GUI 保存通过独立 C2S 通道提交，服务端检查 OP 权限、掩码合法性；非 OP 请求只返回实际服务器策略。策略保存后向在线玩家同步，并关闭被新策略禁止的已打开菜单。子开关和主开关均即时生效；织布机等注册型工作站开关仍需重启。

旧配置保留两个原权限字段，新字段由现有配置系统默认值补齐。新增菜单类型无条件注册，不因收纳袋开关关闭而漏注册。中英、繁中、韩文补齐新增文本。

## 内容安全与兼容

- 可堆叠容器只允许数量为 1 时打开，不拆分、不消耗宿主。
- 带未展开战利品表的容器拒绝打开；超出当前容器实际容量的组件也拒绝打开，不隐藏并覆盖高位槽。
- 原库存、原槽号、原物品引用以及嵌套祖先持续校验，失效时拒绝写入；既有源槽移动/合并保护保留。
- 合成器按原生配方生成结果和返还物，先纯计算背包空间，再消耗材料并提交。宿主和所有祖先槽既不作为产物目标，也不被合成前的背包快照写回，防止旧副本回滚材料组件。实际配方测试曾定位此事务边界问题，已加入引用和持久化消耗断言。
- 仅空的合成器槽可锁；越界按钮、过期引用拒绝执行。锁信息保存在原物品 `BLOCK_ENTITY_DATA.disabled_slots`，其他元数据保持不变。
- 熔炉类、酿造台是原生槽位与内部存储编辑，不模拟持续烧炼/酿造。展示架不模拟红石行为。
- 织布机使用原生菜单，是独立的生存工作站，允许成组物品。
- AMS 仍为可选兼容，沿用规则检测、实际末影箱容量和潜影盒组件防截断，不修改 AMS。
- 旧打开包仍为 4 字节，旧策略包仍为 2 字节。详细策略与 GUI 更新各自使用独立 v2 通道，不扩展旧包。自定义陶罐/展示架/合成器菜单要求对端具备 v2 能力；普通潜影盒保留旧服务器路径。

## 验证方法

在仓库根目录执行：

```powershell
./build.ps1 -JavaHome '<JDK 25>' -GradleArguments @('--offline','--console=plain','--no-daemon')
./build.ps1 -Loader neoforge -JavaHome '<JDK 25>' -GradleArguments @('--offline','--console=plain','--no-daemon')
```

Fabric 经 Fabric/Knot 执行组件、菜单、协议和来源会话回归。NeoForge 除相同回归外，通过官方 EphemeralTestServerProvider 显式创建临时真实世界，在服务端线程测试原生槽位角色、产物合并、空格锁定、真实木板/蛋糕配方、空桶返还、满背包原子拒绝以及源引用替换拒绝。临时世界由测试关闭，不随 mod 打包。

需用户继续游戏内验收：

1. 打开配置的“快捷容器”页，确认三态顺序、重置、保存重开、每个子项开关；用非 OP 与 OP 分别保存，验证服务器权限。
2. 主策略为“创造可用”时分别测试创造/生存；设 true 后生存可用；设 false 后全部受控容器禁用，织布机仍可用。
3. 全部铜箱子、展示架变种手持/背包右击；陶罐只 1 格、展示架只 3 格；关闭重开验证数据。
4. 熔炉类输入/燃料/输出与酿造台药水/原料/燃料限制、Shift 点击正确，不出现漏斗替代界面。
5. 合成器锁空槽、解锁、放材料、合成一次、背包满、返还桶、关闭重开；源槽被替换后不产生结果、不写旧物品。
6. 联机新旧 QuickShulker、AMS 两个大容器规则开/关、后 27 格保留、长按拖拽和嵌套来源并发替换。

自动构建和服务端测试不等于 GUI 视觉验收或 AMS 联合运行验收。最终产物、SHA-256 和实际命令以各 `mod-builds/<时间戳>/build-manifest.json` 为准。
