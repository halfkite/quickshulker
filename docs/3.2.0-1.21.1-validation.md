# 3.2.0 / Minecraft 1.21.1 验证记录

## 范围与审查

- 基线：Fabric / Java 21 / Minecraft 1.21.1。其他 Minecraft 版本和 NeoForge 暂未移植。
- 合并审查上游 1.21.1 提交 `39fd13a01efe415502b90649dec993ae77d51ba3`：音效、快捷键、更新检查、末影箱同步边界、创造槽位映射。
- 修正其创造批量网络回调：全部切回服务端执行线程，检查可选槽位索引及活动源槽锁；不吞异常继续写入。
- 更新检查改查本 fork，并从有效版本标签中选最高版本，不依赖 GitHub 标签返回顺序。
- AMS：仅读取规则字段或 LazySettings API；不修改 AMS 源码、不依赖其注入位置。规则无法读取时警告并保留已存内容，末影箱以实际库存为准。
- 仅参考 Carpet-FGA-Addition 的目录/构建结构，未取用其任何功能代码；多版本单分支整合等待基线验收。

## 根因与改动

旧实现假设快捷物品全部位于玩家背包，且菜单库存尺寸固定；新增容器还可能没有 CONTAINER 组件。简单复用旧菜单会造成错槽、空组件失败或高位物品截断。新增物品库存适配器，按布局展示，保留组件容量，以原库存、原槽号和原对象引用验证每次会话。

长按批量操作与普通菜单共享同一容量保留逻辑；菜单点击、Shift 合并、热键交换和创造批量协议均不得替换活动源物品。失效库存拒绝继续写回。旧版开盒协议保持单个 int，新协议独立通道并先检测服务端能力。

## 自动检查

执行 `gradlew.bat build -PlocalCompatDependencies=true --offline --console=plain --no-daemon`，通过 Fabric Knot 启动独立测试模组，检查真实组件、数据包与 Mixin。测试模组只在测试 sourceSet 中，成功后在创建世界前退出，不进入可分发 jar。

覆盖：旧协议四字节、新旧通道隔离、新协议往返、空容器创建、末槽保存、名字组件不变、大潜影盒第 54 格保留、失效会话拒绝写回、容器布局、填充槽、合成器禁用槽/元数据、原对象及替换副本引用检查。

这不是游戏内联机验收，也不证明 AMS 联合运行已测试。

## 必须执行的游戏回归

请先备份存档，客户端与服务端安装同一候选版本。

1. 无 AMS：普通潜影盒与末影箱 27 格；三个新增工作站输入输出、Shift 点击、关闭返还；旧服务器上普通潜影盒背包右键不崩溃。
2. AMS：分别关闭/开启 `largeShulkerBox` 与 `largeEnderChest`；空盒显示正确容量；在第 54 格存放物品，关闭重开，再长按拖动、批量转移，数量不变。切换规则后已有内容不可被截断。
3. 创造模式：逐一测试箱子、陷阱箱、木桶、漏斗、投掷器、发射器、陶罐、合成器、熔炉、烟熏炉、高炉、酿造台；手持与玩家背包开盒，关闭重开及放置后内容仍在；物品名称/其他组件不变。
4. 一组两个以上的容器不可打开；陶罐额外槽不可用；合成器禁用槽不可用；未展开战利品表拒绝打开；不发生背包内烧炼或红石运作。
5. OP 指令查询、修改并重启服务器，配置仍保留；默认生存禁止；设 `quickContainersCreativeOnly false` 后生存可用；设 `quickContainers false` 后关闭已打开的新容器，但普通/大潜影盒不受影响；非 OP 无权限修改。
6. 从真实箱子槽打开潜影盒，另一个玩家/漏斗替换原槽，菜单安全失效；源槽禁止点击、Shift 合并、数字键/副手交换及批量协议修改。外层快捷箱子物品被替换时，内层潜影盒也不可继续写回。
7. 创造物品目录、结果槽、光标持物、过期菜单同步 ID 和非法槽号不得作为新增容器打开来源。
